# Troubleshooting

Find the message you see. For any `Code:` line the CLI prints, [Refusal codes](/reference/refusals) explains what it means and what to do.

## Starting up

| Symptom                                                                                        | Cause and fix                                                                                                                                                                                                                                                                             |
| ---------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `pnpm demo` or `pnpm migrate` fails with `ECONNREFUSED … 5433`                                 | Postgres isn't ready yet. Wait a few seconds after `pnpm dev` and try again; check Docker Desktop is running.                                                                                                                                                                             |
| `pnpm dev` fails with `failed to connect to the docker API`                                    | Docker Desktop isn't running. Start it and wait until it's ready.                                                                                                                                                                                                                         |
| `pnpm demo` says ports are already in use                                                      | An earlier demo or manual run still holds them. Stop it. If it was killed rather than stopped with Ctrl-C, find the leftovers: `Get-NetTCPConnection -LocalPort 4001,4002,4003,4004,4005 -State Listen` (PowerShell), or `lsof -i :4001` (macOS, Linux), and stop those `node` processes. |
| Something else already uses port 5432                                                          | Expected. Custos's Postgres uses **5433** on purpose.                                                                                                                                                                                                                                     |
| Windows: Docker can't bind port 5433 (`access permissions`, not "in use")                      | Windows NAT reserved the port. From an **elevated** shell: `net stop winnat`, `netsh int ipv4 add excludedportrange protocol=tcp startport=5433 numberofports=1 store=persistent`, `net start winnat`.                                                                                    |
| Revocation exits with `REVOCATION_SIGNING_SEED … expected string`                              | Set the seed in the **same terminal** before starting revocation. Reuse the original seed on restarts.                                                                                                                                                                                    |
| Identity exits with `IDENTITY_ISSUER_SEED … expected string`                                   | Set the seed in the same terminal before starting identity.                                                                                                                                                                                                                               |
| Vault exits with `VAULT_MASTER_KEY … must be 64 hex characters`                                | Set the key in the same terminal before starting the vault.                                                                                                                                                                                                                               |
| A service exits naming `REVOCATION_SERVICE_KEY`, `IDENTITY_SERVICE_KEY` or `VAULT_SERVICE_KEY` | The service key is missing, mistyped, revoked or expired, or it's another service's key. Paste the right line from `pnpm -s custos-admin dev-keys`, or run it again for a fresh set.                                                                                                      |

## Operator commands

| Symptom                                                                                       | Cause and fix                                                                                                                                                                                                                                                            |
| --------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `error: you are not signed in as an operator`                                                 | Set `CUSTOS_OPERATOR_KEY` (from `pnpm demo` or `custos-admin dev-keys`), or sign in with `custos login` if SSO is configured.                                                                                                                                            |
| `401` and `UNAUTHORIZED`                                                                      | The operator key was refused: mistyped, revoked, expired, from another database, or missing the scope. Every reason gives the same answer on purpose. Check `pnpm custos-admin key list`. After 10 failures in 5 minutes your address is also locked out for 15 minutes. |
| `custos register` fails with `refusing to overwrite existing key file` (or `credential file`) | An `agent.key` or `agent.json` from an earlier registration is in the way. Run it in an empty directory, or pass `--key-out <path>` and `--out <path>`.                                                                                                                  |
| `custos register` fails with `STATUS_ALLOCATION_FAILED` or a 502                              | The revocation service isn't running. Identity needs it to reserve the agent's revocation slot, and refuses to create an agent that couldn't be revoked.                                                                                                                 |
| `custos grant` says `say which agent gets the tool, one way only`                             | Give exactly one of `--to <agent id>` and `--credential <file>`.                                                                                                                                                                                                         |

## Using a tool

| Symptom                                                                      | Cause and fix                                                                                                                                                                                                                                                                                    |
| ---------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Every call refused with `INVALID_AGENT_CREDENTIAL` after restarting identity | Identity was restarted with a **different** `IDENTITY_ISSUER_SEED` (every `pnpm demo` run uses a new one), so earlier credentials no longer verify. Restart with the original seed, or register agents again.                                                                                    |
| `INVALID_PROOF_OF_POSSESSION (WRONG_AUDIENCE)`                               | The vault's `VAULT_PUBLIC_URL` isn't the address you're calling. Requests are signed for the exact URL, so `localhost` and `127.0.0.1` differ. Use `--vault-url` matching `VAULT_PUBLIC_URL` (default `http://localhost:4002`).                                                                  |
| `INVALID_PROOF_OF_POSSESSION (SIGNATURE_INVALID)`                            | The key doesn't match the credential: the wrong `agent.key` for this `agent.json`.                                                                                                                                                                                                               |
| `error: no agent key at agent.key`                                           | Run `use` from the directory where you registered, or pass `--key <path>`.                                                                                                                                                                                                                       |
| `REVOCATION_STATE_STALE` on every call                                       | The vault can't reach the revocation service, so it refuses rather than risk allowing a revoked agent. Start revocation; the vault catches up within about 10 seconds. It also happens if the two services' clocks differ by more than a few seconds (`REVOCATION_LIST_MAX_CLOCK_SKEW_SECONDS`). |
| `UNKNOWN_TOOL` (404)                                                         | The tool's credential isn't in the vault, or the name is misspelled. Store it: `pnpm --filter @custos/vault seed <tool> <secret>`.                                                                                                                                                               |
| `500` with `invalid tag`                                                     | The stored tool credential was encrypted under a different `VAULT_MASTER_KEY`. Store the credentials again.                                                                                                                                                                                      |
| `--input is not JSON`                                                        | Quote the JSON for your shell, for example `--input '{"table":"customers"}'`. On Windows use PowerShell 7+, not Windows PowerShell 5.1.                                                                                                                                                          |

## The audit log

| Symptom                                        | Cause and fix                                                                                                                                                                                                                   |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `custos audit-log` stops with `KEY_CHANGED`    | The audit service now seals with a new key (every `pnpm demo` run, unless `AUDIT_SIGNING_SEED` stays set). Check the key against the `audit seal key` line `pnpm demo` printed, then run `custos audit-log --accept-key <key>`. |
| `note: no outside seal store was checked`      | Set `CUSTOS_AUDIT_SEAL_STORE_URL` to the seal store's read-only user (`pnpm demo` prints it).                                                                                                                                   |
| Every check fails after resetting the database | Reset the main database and the seal store **together** (`pnpm dev:down`, then remove both Docker volumes). A fresh log next to old seal copies clashes with them.                                                              |
